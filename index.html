Settings & data sources

Every board works without a key. Keys are stored only in this browser and sent only to the provider they belong to.

Washington Metro (optional)

Boards already run live through Transitous. A free key from developer.wmata.com (default tier) switches to WMATA's own predictions, which add the number of cars and WMATA's short destination names.

London (optional)

London runs without a key. If a board ever stalls on TfL's anonymous rate limit, a free key from api-portal.tfl.gov.uk raises it.

Boston (optional)

Boston runs without a key at up to 20 requests a minute. A free key from api-v3.mbta.com raises that if you run several screens.

Chicago (Worker address)

Chicago's arrivals come through your own Cloudflare Worker, which holds the CTA key (see worker/README.md). The address is normally set in data/systems.js; anything typed here overrides it in this browser only.

About the data

Live only. Every train on screen comes from a real-time prediction. Scheduled trips with no live data are never shown, and if a system's feed goes quiet the board says so instead.

New York: MTA GTFS-realtime. Washington, Paris and Berlin: operator real-time data (WMATA, Île-de-France Mobilités, VBB/BVG) via Transitous (map data © OpenStreetMap contributors), or WMATA directly with a key. London: TfL Unified API (powered by TfL Open Data). Stockholm: SL Transport API via Trafiklab. Hong Kong: MTR Next Train (DATA.GOV.HK). Chicago: CTA Train Tracker, with predictions CTA marks as schedule-based left out. Boston: MBTA V3 API. Prague and Helsinki: PID and HSL real-time data via Transitous.

Board styles are evocations of each system's platform screens. No operator logos or proprietary typefaces are used. The chime is an original two-note figure.
